# 铁路桩号换版核查

铁路台账只存桩号。换版前，用这个网页工具核查：哪些旧号能自动迁移、对应哪个新号；
哪些必须先补段号或人工处理。

## 规则

桩号表每行一段，四列：

| 段号 | 里程起点 | 里程终点 | 起点桩号 |
|------|----------|----------|----------|
| K1   | 0        | 500      | 1000     |
| K2   | 500      | 900      | 1500     |

* 里程与桩号均为**整数米**；
* 里程区间**左闭右开**：`[里程起点, 里程终点)`；
* 段内每增加 1 米，桩号加 1：桩号区间为 `[起点桩号, 起点桩号 + 里程长度)`。

一个旧号 `x` 只有在以下四条全部成立时才判为**可迁移**：

1. 旧表中恰好一个段覆盖 `x`（旧号在全线唯一）；
2. 该工程里程在旧表中恰好对应一个段（否则一个位置对应多个旧号，无法判断迁移谁）；
3. 新表中恰好一个段覆盖该工程里程（该工程位置有新号）；
4. 换算出的新号在新表中恰好出现一次（新号在全线唯一）。

其余旧号按区间分类，并列出相关段号：

| 状态 | 含义 |
|------|------|
| 可迁移 | 四条件全满足，给出旧号区间与对应新号区间 |
| 缺号 | 旧表没有任何段覆盖该桩号，先补段号/补录 |
| 重号（旧表） | 旧表桩号区间重叠，或同一工程里程对应多个旧号 |
| 新表未覆盖 | 新表没有覆盖该工程里程，先在新表补段 |
| 重号（新表） | 同一工程里程在新表被多段覆盖，或算出的新号在新表重复 |

“相关段号”一列：可迁移区间显示“旧段号 → 新段号”，异常区间显示涉及的段号
（缺号显示前后相邻旧段，新表未覆盖显示前后相邻新段）。

> 注：桩号本身不是连续编号的“公里标 K1+234”文本，工具按**整数米**数值处理，
> 例如 `起点桩号 1000` 表示 1000 m。

### 长区间不逐米展开

算法收集旧号空间中分类可能变化的边界（旧段桩号端点、新旧段里程交叠端点、
新号重叠区映射回旧号的端点），把查询区间切成若干段，每段取一个样本点判定，
再合并相邻同状态区间。复杂度只与**段数和边界数**有关，与区间长度无关：
1 亿米长的区间也只有几个区间输出，耗时毫秒级。

## 运行（Docker Compose）

```bash
docker compose up --build
```

打开 <http://localhost:8000>。页面内提供两份示例表下载：

* `samples/old_v1.csv` / `samples/new_v1.csv`（旧号 1000–2499）
* 示例故意包含：可迁移、缺号、旧表重号、新表未覆盖、新表重号五类情况。

停止：`docker compose down`。

## 本地开发 / 测试

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
pip install pytest httpx
pytest -q
uvicorn app.main:app --reload
```

## 输入格式

* 支持 CSV（UTF-8 / UTF-8 BOM / GB18030，逗号、分号或制表符分隔）和 XLSX（首个工作表）；
* 表头支持中文（段号, 里程起点, 里程终点, 起点桩号）或英文
  （segment_no, start_mileage_m, end_mileage_m, start_chainage）；
* 文件 ≤ 20 MB；单元格必须为整数，`1.5` 这类小数会被拒绝并报告行号。

## 输出与下载

* 页面按区间列出全部核查结果；
* “下载可迁移区间 CSV”**只含可迁移区间**，列为：
  `旧号起, 旧号止, 旧号个数, 新号起, 新号止, 旧段号, 新段号`；
* 下载链接指向内存中的结果，有效期 1 小时或直到服务重启，需重新核查。

## 已知限制

* 只接受整数米；不做“K1+234”文本格式解析（如需要可先转成整数米）。
* 结果缓存为单进程内存，多副本部署时应改为共享缓存；当前 compose 只起一个实例。
* XLSX 只读第一个工作表。
* 不判断桩号方向（里程递增而桩号递减），只按“段内每米加一”处理；若业务上存在
  桩号随里程递减的段，需要另行约定。
* 实际耗时随**段数**增长：5000 段约 0.2 秒；接近 90 万段（约 28 MB CSV）解析约
  25 秒、核查约 40 秒。段数极多时建议先在台账中筛出目标线路/区段。

## 验证情况

* `pytest`：91 个用例全部通过，覆盖区间分类、CSV/XLSX 解析、错误输入、
  下载内容与 HTTP 端到端流程。
* 另以逐米枚举为基准，对 9000 组随机表（含桩号重叠、里程重叠、缺段、空隙）
  做对照，结果完全一致。
* 1 亿米长的查询区间在网页流程中毫秒级返回，未逐米展开。
* Docker 镜像未在本机实际构建验证（开发环境无 Docker 守护进程）；
  `docker-compose.yml` 已通过 YAML 解析校验，依赖在干净虚拟环境中按
  `requirements.txt` 安装并成功启动服务。
